# YouTube embeds in API v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every v3 entry object carries a `videos` list with the poster, title, channel, duration, live status and chapters of each YouTube video iframed in its `content.html`, and entries whose video data arrives late are marked edited so clients refetch them.

**Architecture:** A new `entry_videos` table records which entries iframe which YouTube videos, written when `HarvestEmbeds` scans an entry. Serving reads the video ids from the stored API rendering and loads their `Embed` rows for a whole page at once (`Api::V3::VideoLoader`), serialized by `Api::V3::VideoSerializer`. When `HarvestEmbeds::Download` stores video rows, or `ImageCrawler::ChannelImage` stores a channel avatar, the mapped entries get `revision + 1` and `edited_at = now`.

**Tech Stack:** Rails 8.1, Postgres (`db/structure.sql`), Sidekiq, Minitest with WebMock.

**Spec:** `docs/superpowers/specs/2026-11-03-api-youtube-embeds-design.md`

## Global Constraints

- YouTube only. Vimeo and other providers are untouched.
- Iframes only: ids from `<a href>` links are still harvested as today but never mapped or listed.
- `content.html` does not change. No `ContentFormatter::VERSION` bump.
- `videos` is always present on the entry object, `[]` when there are none. Not an `expand=` name.
- A video with no `youtube_video` `Embed` row is left out of `videos`.
- The edit bump is `revision = revision + 1, edited_at = <now>` via `update_all` (no callbacks, no re-render), the same pair `FeedCrawler::EntryUpdate` sets.
- No backfill of harvests or of `entry_videos` rows for entries harvested before this ships (decided; see spec).
- Video data is read at response time, never stored in the rendering.
- Run tests with `source ~/.bash_profile && bin/rails test <path>`; the full suite is `bundle exec rake`.

## Review Focus

1. **The same video iframed twice in one entry** → one item, at its first position. Test in Task 3.
2. **Every iframe spelling** (`youtube-nocookie.com/embed/ID`, `youtube.com/embed/ID?start=30&rel=0`, `youtube.com/shorts/ID`) → recognized by `config/initializers/youtube.rb`'s patterns. Test in Task 3.
3. **A video row whose channel row is missing, or whose channel avatar isn't crawled** → `channel: null` / `channel.icon: null`, not an exception. Tests in Task 2.
4. **A bump with nothing to bump** (no mapped entries; blank channel id) → updates zero rows. It must never fall through to an unscoped `update_all`. Tests in Task 1.
5. **Entry created, synced, then harvested before its mapping row was written** (the Parser path queues ids before the entry exists) → `find_embeds` bumps the entry itself when a video's row was stored after the entry was created. Test in Task 4.

### Task 1: `entry_videos` table and the bump

**Files:**
- Create: `db/migrate/20261103120000_create_entry_videos.rb`, `app/models/entry_video.rb`
- Modify: `db/structure.sql` (regenerated by the migration), `app/models/entry.rb` (association)
- Test: `test/models/entry_video_test.rb`

**Interfaces:**
- Produces:
  - Table `entry_videos(entry_id bigint NOT NULL, provider_id text NOT NULL, created_at timestamp NOT NULL)`, unique index on `(provider_id, entry_id)`, index on `entry_id`, FK to `entries(id)` `ON DELETE CASCADE` (as the other entry FKs in structure.sql do). No `id` column.
  - `EntryVideo.record(entry_id:, provider_ids:) -> void` — inserts missing rows (`insert_all` with `unique_by`), no-op for empty `provider_ids`.
  - `EntryVideo.bump_for_videos(provider_ids) -> Integer` — rows updated; `0` and no query for empty input.
  - `EntryVideo.bump_for_channel(channel_id) -> Integer` — entries mapped to any `Embed.youtube_video` row whose `parent_id` is `channel_id`; `0` for blank `channel_id`.
  - `EntryVideo.bump(entry_ids_relation) -> Integer` — the shared `update_all("revision = revision + 1, edited_at = ...")` both bump methods use.
  - `Entry has_many :entry_videos` (no `dependent:`; the FK cascades).

### Task 2: `Api::V3::VideoSerializer`

**Files:**
- Create: `app/serializers/api/v3/video_serializer.rb`
- Test: `test/serializers/api/v3/video_serializer_test.rb`

**Interfaces:**
- Consumes: `Embed` (`#chapters`, `#duration_in_seconds`, `#live_broadcast_content`, `#scheduled_time`, `#data`), `Api::V3::ImageSerializer`.
- Produces: `Api::V3::VideoSerializer.new(video, channel: nil, channel_image: nil).to_h -> Hash` where `video` is a `youtube_video` `Embed`, `channel` its `youtube_channel` `Embed` or nil, `channel_image` that channel's avatar `Image` or nil. Hash, in this key order:
  `object: "video", provider: "youtube", id:, url: "https://youtu.be/#{id}", title:, duration_in_seconds:, live:, scheduled_start_at:, poster:, channel:, chapters:`
  - `title`: `snippet.title`.
  - `live`: `live_broadcast_content || "none"`.
  - `scheduled_start_at`: `scheduled_time&.utc&.iso8601`.
  - `poster`: the first of `maxres standard high medium default` present in `snippet.thumbnails`, as `{url:, width:, height:}`; nil when none.
  - `channel`: `{id: channel.provider_id, title: channel snippet.title, icon: ImageSerializer hash or nil}`, or nil without a channel row.
  - `chapters`: `video.chapters.map { {start_in_seconds: it[:seconds], title: it[:title], duration_in_seconds: it[:duration]} }`.

### Task 3: `Api::V3::VideoLoader` and `videos` on the entry

**Files:**
- Create: `app/models/api/v3/video_loader.rb`
- Modify: `app/serializers/api/v3/entry_serializer.rb`, `app/controllers/concerns/api/v3/expansion.rb:24-28`, `app/controllers/api/v3/feeds/lookups_controller.rb:23`
- Test: `test/models/api/v3/video_loader_test.rb`, `test/serializers/api/v3/entry_serializer_test.rb`, `test/integration/api_v3_entries_test.rb`

**Interfaces:**
- Consumes: `Api::V3::VideoSerializer` (Task 2), `Entry#rendering.api`, `IframeEmbed::Youtube.recognize_url?`.
- Produces:
  - `Api::V3::VideoLoader.video_ids(html) -> Array<String>` — YouTube ids of `<iframe>` srcs in `html`, first-appearance order, unique; `[]` for nil. A regex scan of `<iframe ... src="...">`, not a Nokogiri parse, then `recognize_url?(src)[1]`.
  - `Api::V3::VideoLoader.call(entries) -> Hash{Integer => Array<Hash>}` — every entry id, mapped to its serialized videos. Three queries for any number of entries: video rows, channel rows, channel avatar images (`Image.provider_embed_icon` by channel `provider_id`, as `Embed#channel_image`).
  - `EntrySerializer.new(entry, ..., videos: nil)` — `to_h` gains `videos:` after `attachments:`. `nil` means compute for this one entry via `VideoLoader.call([entry])`.
  - `serialize_entries` and the lookups controller pass `videos:` from one `VideoLoader.call(entries)`.

### Task 4: Record mappings and bump on harvest

**Interfaces:**
- Consumes: `EntryVideo.record`, `EntryVideo.bump_for_videos`, `EntryVideo.bump_for_channel` (Task 1).
- Produces: no new public API.
  - `HarvestEmbeds#find_embeds` collects iframe ids and `data["youtube_video_id"]` separately from link ids; calls `EntryVideo.record(entry_id:, provider_ids: iframe_ids)`; then bumps the entry (`EntryVideo.bump(Entry.where(id: entry.id))`) when any of those ids already has a `youtube_video` `Embed` row with `updated_at > entry.created_at` (Review Focus 5). Link ids are still queued as today.
  - `HarvestEmbeds::Download#update_related_records(ids)` calls `EntryVideo.bump_for_videos(videos.map(&:provider_id))` — only ids that came back with a row. Live re-downloads go through the same path, so they bump too.
  - `ImageCrawler::ChannelImage#perform` calls `EntryVideo.bump_for_channel(channel_id)` after the existing blank guard.
