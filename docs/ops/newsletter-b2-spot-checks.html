Newsletter B2 spot checks

Run each block in a production Rails console. Each block is self-contained. The main runbook is newsletter-b2-runbook.html.

The blocks that read from B2 over HTTP need the bucket to be public. A 403 means it is not.

  1. Run right after Deploy A. It proves that the key can reach the bucket and write to it. It leaves nothing behind. 
    begin
  bucket = ENV["NEWSLETTERS_BUCKET"]
  raise "NEWSLETTERS_BUCKET is not set" if bucket.blank?
  client = NewsletterPage.storage_client
  puts "bucket: #{bucket}"
  puts "endpoint: #{ENV["UNIFIED_ENDPOINT"]}"
  listing = client.get_bucket(bucket, "max-keys" => 1)
  puts "list status: #{listing.status}"
  key = "_spotcheck/#{Time.now.to_i}.txt"
  puts "put status: #{client.put_object(bucket, key, "ok", "Content-Type" => "text/plain").status}"
  puts "delete status: #{client.delete_object(bucket, key).status}"
end
    Expect: list 200, put 200, delete 204. An exception names the cause: a 403 is a key without access, a 404 is a wrong bucket name.
  2. It saves a real newsletter page, then reads it from B2 over HTTP with a gzip request. 
    begin
  entry = Feed.newsletter.last.entries.order(:id).last
  page = NewsletterPage.new(entry)
  puts "entry: #{entry.id}"
  puts "key: #{page.key}"
  page.save
  uri = URI("#{ENV["UNIFIED_ENDPOINT"]}/#{ENV["NEWSLETTERS_BUCKET"]}/#{page.key}")
  response = Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") { |http| http.get(uri.request_uri, "Accept-Encoding" => "gzip") }
  puts "status: #{response.code}"
  puts "content-encoding: #{response["content-encoding"].inspect}"
  puts "content-type: #{response["content-type"].inspect}"
  puts "cache-control: #{response["cache-control"].inspect}"
  html = ActiveSupport::Gzip.decompress(response.body).force_encoding(Encoding::UTF_8)
  puts "decompressed bytes: #{html.bytesize}"
  puts "has title: #{html.include?("<title>")}"
  puts "matches a fresh build: #{html == page.document.to_html}"
end
    Expect: status 200, content-encoding "gzip", content-type "text/html; charset=utf-8", cache-control "max-age=315360000, public", has title true, matches a fresh build true.
  3. It takes five random newsletter feeds and sends a HEAD request for the first entry of each. 
    begin
  ids = Feed.newsletter.limit(500).pluck(:id).sample(5)
  puts "feeds sampled: #{ids.size}"
  ids.each do |feed_id|
    entry = Entry.where(feed_id: feed_id).order(:id).first
    if entry.nil?
      puts "feed #{feed_id}: no entries"
      next
    end
    key = NewsletterPage.new(entry).key
    uri = URI("#{ENV["UNIFIED_ENDPOINT"]}/#{ENV["NEWSLETTERS_BUCKET"]}/#{key}")
    response = Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") { |http| http.head(uri.request_uri) }
    puts "feed #{feed_id} #{key}: status #{response.code}, content-encoding #{response["content-encoding"].inspect}"
  end
end
    Expect: status 200 and content-encoding "gzip" on every line. A 404 on an entry with content means the backfill missed it. Run the backfill again.
  4. It runs the real saver on the newest entry of a newsletter feed. That entry already has its public URL, so the URL must not change. 
    begin
  entry = Feed.newsletter.last.entries.order(:id).last
  before = entry.url
  NewsletterSaver.new.perform(entry.id)
  entry.reload
  puts "url before: #{before}"
  puts "url after: #{entry.url}"
  puts "url changed: #{before != entry.url}"
  puts "NEWSLETTER_HOST: #{ENV["NEWSLETTER_HOST"].inspect}"
  puts "S3 dual write on: #{ENV["AWS_S3_BUCKET_NEWSLETTERS"].present?}"
end
    Expect: url changed false. "S3 dual write on" is true until Deploy B, then false.
  5. It proves that the dual write reaches S3, which the CDN still reads until the origin moves. 
    begin
  bucket = ENV["AWS_S3_BUCKET_NEWSLETTERS"]
  raise "AWS_S3_BUCKET_NEWSLETTERS is not set" if bucket.blank?
  entry = Feed.newsletter.last.entries.order(:id).last
  key = NewsletterPage.new(entry).key
  puts "key: #{key}"
  begin
    puts "S3 status: #{Fog::Storage.new(STORAGE).head_object(bucket, key).status}"
  rescue Excon::Error::NotFound
    puts "S3 status: 404"
  end
end
    Expect: S3 status 200 for an entry saved after Deploy A. Run check 4 first if it says 404.
  6. It requests the same entry from NEWSLETTER_HOST with a gzip request. It also requests a key that does not exist. 
    begin
  entry = Feed.newsletter.last.entries.order(:id).last
  url = entry.newsletter_url
  puts "url: #{url}"
  uri = URI(url)
  response = Net::HTTP.start(uri.host, uri.port, use_ssl: true) { |http| http.get(uri.request_uri, "Accept-Encoding" => "gzip") }
  puts "status: #{response.code}"
  puts "content-encoding: #{response["content-encoding"].inspect}"
  puts "content-type: #{response["content-type"].inspect}"
  puts "cache-control: #{response["cache-control"].inspect}"
  puts "readable html: #{ActiveSupport::Gzip.decompress(response.body).include?("<title>")}"
  missing = URI("https://#{uri.host}/zzz/missing-spot-check.html")
  puts "missing key status: #{Net::HTTP.start(missing.host, missing.port, use_ssl: true) { |http| http.head(missing.request_uri) }.code}"
end
    Expect: status 200, the same three headers as check 2, readable html true, missing key status 404. A missing "content-encoding" means the CDN removed the header or decompressed the body. To roll back, point the CDN origin at S3 again.
