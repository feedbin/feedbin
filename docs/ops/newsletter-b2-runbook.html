Newsletter pages to B2

Spec: docs/superpowers/specs/2026-10-05-newsletter-storage-b2-design.md. Run each Ruby block in a production Rails console. Each block is self-contained.

The checks read B2 over HTTP with no credentials, the way the CDN does. A 401 or 403 there means the bucket is not public.

Before Deploy A

  1. This runs on the code in production today. Since 2022 the saver stored NEWSLETTER_HOST plus the S3 response path. The B2 origin serves /<key> only. If the stored path holds anything else, such as an S3 bucket name, those links break at the cutover. 
    begin
  host = ENV["NEWSLETTER_HOST"]
  puts "NEWSLETTER_HOST: #{host.inspect}"
  entries = Feed.newsletter.order(id: :desc).limit(20).flat_map { it.entries.order(id: :desc).limit(5).to_a }
  on_host = entries.select { it.url.to_s.start_with?("https://#{host}/") }
  puts "entries sampled: #{entries.size}"
  puts "url on NEWSLETTER_HOST: #{on_host.size}"
  puts "url equals newsletter_url: #{on_host.count { it.url == it.newsletter_url }}"
  on_host.reject { it.url == it.newsletter_url }.first(3).each { puts "differs: #{it.url} (expected #{it.newsletter_url})" }
end
    Expect: the last two counts are equal and no "differs" lines. If they differ, stop. The stored URLs need a fix before this migration.
  2. Make a B2 bucket in the same account as the image store.
    • Set it to public.
    • Set its lifecycle to "Keep only the last version of the file". B2 keeps every version by default, and each re-save of a page would be stored and billed again.
    • Make sure the UNIFIED_* application key is allowed on this bucket. A key restricted to the image bucket is not.
  3. In 1Password, open the item feedbin in the Development vault. In the production_env field, add NEWSLETTERS_BUCKET with the name of the bucket from the previous step. Do not change AWS_S3_BUCKET_NEWSLETTERS. The saver needs it for the dual write. The deploy uploads this field as .env.

Deploy A: write to S3 and B2

  1. Capistrano deploys main from GitHub. 
    cd ~/Sites/feedbin
git switch main
git merge --ff-only newsletter
git push origin main
  2. The deploy pauses Sidekiq, uploads .env, and restarts the web and background services. There is no migration. 
    cd ~/Sites/deploy/feedbin
bundle exec cap production deploy
    From now on the saver writes each new page to S3 first, then to B2. The CDN still reads S3.
  3. This writes a small gzip page with the real headers, reads it back with no credentials, and deletes it. 
    begin
  bucket = NewsletterPage.bucket
  client = NewsletterPage.storage_client
  key = "_spotcheck/#{Time.now.to_i}.html"
  puts "bucket: #{bucket}"
  puts "put status: #{client.put_object(bucket, key, ActiveSupport::Gzip.compress("<title>spot check</title>"), NewsletterPage::HEADERS).status}"
  uri = URI("#{ENV["UNIFIED_ENDPOINT"]}/#{bucket}/#{key}")
  response = Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") { |http| http.get(uri.request_uri, "Accept-Encoding" => "gzip") }
  puts "public read status: #{response.code}"
  puts "content-encoding: #{response["content-encoding"].inspect}"
  puts "content-type: #{response["content-type"].inspect}"
  puts "cache-control: #{response["cache-control"].inspect}"
  puts "body: #{ActiveSupport::Gzip.decompress(response.body)}" if response.code == "200"
  puts "delete status: #{client.delete_object(bucket, key).status}"
end
    Expect: put 200, public read 200, content-encoding "gzip", content-type "text/html; charset=utf-8", cache-control "max-age=315360000, public", body "<title>spot check</title>", delete 204. An exception on the put names the cause: 403 is a key without access to the bucket, 404 is a wrong bucket name. If this fails, stop. New newsletters still reach S3, so nothing is broken for readers. Sidekiq retries the B2 writes once the cause is fixed.
  4. This runs the real saver on the newest entry of a recent newsletter feed. Then it reads the B2 copy and, during the dual write, the S3 copy. Each copy must carry a Last-Modified from this run. 
    begin
  entry = Feed.newsletter.order(id: :desc).limit(20).lazy.filter_map { it.entries.order(:id).last }.first
  page = NewsletterPage.new(entry)
  before = entry.url
  started = Time.now - 30
  NewsletterSaver.new.perform(entry.id)
  dual = ENV["AWS_S3_BUCKET_NEWSLETTERS"].present?
  puts "entry: #{entry.id}"
  puts "key: #{page.key}"
  puts "url changed: #{before != entry.reload.url}"
  puts "S3 dual write on: #{dual}"
  uri = URI("#{ENV["UNIFIED_ENDPOINT"]}/#{NewsletterPage.bucket}/#{page.key}")
  response = Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") { |http| http.get(uri.request_uri, "Accept-Encoding" => "gzip") }
  puts "B2 status: #{response.code}"
  puts "B2 written by this run: #{Time.httpdate(response["last-modified"]) >= started}"
  puts "B2 content-encoding: #{response["content-encoding"].inspect}"
  puts "B2 matches a fresh build: #{ActiveSupport::Gzip.decompress(response.body).force_encoding(Encoding::UTF_8) == page.document.to_html}"
  if dual
    s3 = Fog::Storage.new(STORAGE).head_object(ENV["AWS_S3_BUCKET_NEWSLETTERS"], page.key)
    puts "S3 written by this run: #{Time.httpdate(s3.headers["Last-Modified"]) >= started}"
  end
end
    Expect: url changed false, S3 dual write on true, B2 status 200, B2 written by this run true, B2 content-encoding "gzip", B2 matches a fresh build true, S3 written by this run true. If this fails, stop, for the same reason as the previous step.

Backfill

  1. begin
  workers = Sidekiq::ProcessSet.new.select { it["queues"].include?("backfill") }
  puts "processes on the backfill queue: #{workers.size}"
  workers.each { puts "#{it["hostname"]}: concurrency #{it["concurrency"]}" }
end
    Expect: 2 processes, concurrency 20 each.
  2. It enqueues one job for each newsletter feed. It refuses to start while an earlier pass still has jobs out. 
    begin
  NewsletterBackfill.new.build
  puts NewsletterBackfill.progress
end
  3. Run this block until pending is 0. 
    begin
  puts NewsletterBackfill.progress
  puts "queued: #{Sidekiq::Queue.new("backfill").size}"
  puts "retrying: #{Sidekiq::RetrySet.new.count { it.klass == "NewsletterBackfill" }}"
  puts "dead: #{Sidekiq::DeadSet.new.count { it.klass == "NewsletterBackfill" }}"
end
    Expect at the end: pending 0, mismatched 0, queued 0, retrying 0, dead 0.
    • A job that fails retries by itself. It counts only when it finishes.
    • If pending stays above 0 while queued and retrying are 0, some jobs are dead. Run the next step.
    • If mismatched is above 0, stop before the cutover. Those entries have a URL on NEWSLETTER_HOST that the B2 origin will not serve.
  4. begin
  dead = Sidekiq::DeadSet.new.select { it.klass == "NewsletterBackfill" }
  puts "dead jobs: #{dead.size}"
  dead.map { it.item["error_message"] }.uniq.first(3).each { puts "error: #{it}" }
  dead.each(&:retry)
  puts "retried: #{dead.size}"
end
    Fix the cause the errors name first. Then go back to the previous step.
  5. This takes five random newsletter feeds and sends a HEAD request for the oldest entry of each. 
    begin
  bucket = NewsletterPage.bucket
  ids = Feed.newsletter.limit(500).pluck(:id).sample(5)
  puts "feeds sampled: #{ids.size}"
  ids.each do |feed_id|
    entry = Entry.where(feed_id: feed_id).order(:id).first
    if entry.nil?
      puts "feed #{feed_id}: no entries"
      next
    end
    key = NewsletterPage.new(entry).key
    uri = URI("#{ENV["UNIFIED_ENDPOINT"]}/#{bucket}/#{key}")
    response = Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") { |http| http.head(uri.request_uri) }
    puts "feed #{feed_id} #{key}: status #{response.code}, content-encoding #{response["content-encoding"].inspect}"
  end
end
    Expect: status 200 and content-encoding "gzip" on every line. A 404 means the backfill missed that feed. Check step 10.

Cutover

  1. Point the origin of the NEWSLETTER_HOST CDN at the B2 bucket. Map the public path /<key> to /<bucket>/<key> on the B2 endpoint. The CDN must pass Content-Encoding through and must not decompress the body.
  2. This reads a new page from NEWSLETTER_HOST with a gzip request. Then it requests the stored URL of five old entries, and a key that does not exist. 
    begin
  host = ENV["NEWSLETTER_HOST"]
  head = ->(url) { uri = URI(url); Net::HTTP.start(uri.host, uri.port, use_ssl: true) { |http| http.head(uri.request_uri) } }
  entry = Feed.newsletter.order(id: :desc).limit(20).lazy.filter_map { it.entries.order(:id).last }.first
  uri = URI(entry.newsletter_url)
  response = Net::HTTP.start(uri.host, uri.port, use_ssl: true) { |http| http.get(uri.request_uri, "Accept-Encoding" => "gzip") }
  puts "new page: #{uri}"
  puts "status: #{response.code}"
  puts "content-encoding: #{response["content-encoding"].inspect}"
  puts "content-type: #{response["content-type"].inspect}"
  puts "cache-control: #{response["cache-control"].inspect}"
  puts "readable html: #{ActiveSupport::Gzip.decompress(response.body).include?("<title>")}"
  Feed.newsletter.limit(500).pluck(:id).sample(5).each do |feed_id|
    old = Entry.where(feed_id: feed_id).order(:id).first
    next if old.nil?
    if old.url.to_s.start_with?("https://#{host}/")
      puts "old stored url #{old.url}: status #{head.(old.url).code}"
    else
      puts "old stored url #{old.url}: not on NEWSLETTER_HOST, skipped"
    end
  end
  puts "missing key status: #{head.("https://#{host}/zzz/missing-spot-check.html").code}"
end
    Expect: status 200, the same three headers as step 6, readable html true, status 200 on every old stored URL on the host, and missing key status 404. No content-encoding means the CDN removed the header or decompressed the body. If this fails, point the origin at S3 again. S3 still holds every page until Deploy B.

Deploy B: write to B2 only

Deploy B only after step 14 passes. Until the CDN reads B2, a page saved only to B2 is a 404 for readers. The Deploy B code is on newsletter, so any merge of that branch to main ships it.

  1. In the production_env field of the 1Password item feedbin, remove AWS_S3_BUCKET_NEWSLETTERS. The new code no longer reads it. This only tidies the env.
  2. This ships the saver without the S3 write. 
    cd ~/Sites/feedbin
git switch main
git merge --ff-only newsletter
git push origin main
    cd ~/Sites/deploy/feedbin
bundle exec cap production deploy
  3. This runs the real saver on the newest entry of a recent newsletter feed and reads the B2 copy back. 
    begin
  entry = Feed.newsletter.order(id: :desc).limit(20).lazy.filter_map { it.entries.order(:id).last }.first
  page = NewsletterPage.new(entry)

  NewsletterSaver.new.perform(entry.id)
  puts "entry: #{entry.id}"

  puts "url changed: #{before != entry.reload.url}"
  puts "saver writes to S3: #{NewsletterSaver.method_defined?(:legacy_save)}"
  uri = URI("#{ENV["UNIFIED_ENDPOINT"]}/#{NewsletterPage.bucket}/#{page.key}")
  response = Net::HTTP.start(uri.host, uri.port, use_ssl: uri.scheme == "https") { |http| http.get(uri.request_uri, "Accept-Encoding" => "gzip") }
  puts "B2 status: #{response.code}"

    Expect: url changed false, saver writes to S3 false, B2 status 200, B2 written by this run true, B2 content-encoding "gzip", B2 matches a fresh build true. The migration is complete at this step. From now on a rollback to S3 would miss every page saved after Deploy B.
  4. When you no longer need the rollback, delete the old S3 newsletter bucket.
