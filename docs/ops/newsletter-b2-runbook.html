Newsletter pages to B2

Spec: docs/superpowers/specs/2026-10-05-newsletter-storage-b2-design.md

  1. Make a public B2 bucket in the same account as the image store. Make sure the UNIFIED_* application key can write to it. Set NEWSLETTERS_BUCKET to its name on the web and Sidekiq hosts. Leave AWS_S3_BUCKET_NEWSLETTERS set.
  2. Deploy the branch. New newsletters now go to B2 and to S3.
  3. In a Rails console, run this block. It prints a curl command. 
    begin
  entry = Entry.joins(:feed).where(feeds: {feed_type: Feed.feed_types[:newsletter]}).last
  page = NewsletterPage.new(entry)
  page.save
  puts "curl -sI -H 'Accept-Encoding: gzip' #{ENV["UNIFIED_ENDPOINT"]}/#{ENV["NEWSLETTERS_BUCKET"]}/#{page.key}"
end
    Run the printed command. The response must show content-encoding: gzip, content-type: text/html; charset=utf-8, and cache-control: max-age=315360000, public. If the response is 403 or 404, stop. The bucket is not public or the key has no access.
  4. Make sure both Sidekiq servers (20 threads each) run the backfill queue. Run this block. Run it again later to read the counters. 
    begin
  NewsletterBackfill.new.build
  puts NewsletterBackfill.progress
end
    The pass is done at pending: 0. Check skipped. A non-zero value counts entries that have no content.
  5. Run the block from the previous step. This covers any feed job that failed in the first pass. Wait for pending: 0.
  6. Point the origin of the NEWSLETTER_HOST CDN at the B2 bucket. Map the public path /<key> to /<bucket>/<key> on the B2 endpoint. Then run this block and run the curl command it prints. 
    begin
  entry = Entry.joins(:feed).where(feeds: {feed_type: Feed.feed_types[:newsletter]}).last
  puts "curl -sI -H 'Accept-Encoding: gzip' #{entry.newsletter_url}"
  puts "curl -s --compressed #{entry.newsletter_url} | head -c 300"
end
    The first command must show the same three headers as the probe. The second must print readable HTML. To roll back, point the origin at S3 again.
  7. Unset AWS_S3_BUCKET_NEWSLETTERS on the web and Sidekiq hosts. Restart Sidekiq. The saver now writes to B2 only. The migration is complete at this step.
  8. When you no longer need the rollback, delete the old S3 newsletter bucket.
